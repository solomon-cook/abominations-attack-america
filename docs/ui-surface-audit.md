# Frontend surface audit ledger

This ledger separates existing interaction evidence from full surface acceptance. A happy-path browser run, component render verifier, source-only accessibility contract, and manual visual/assistive-technology review prove different things. A grouped row marked partial does not mean every control in that group was reviewed.

The scope covers gameplay and non-game flows. The browser evidence cited here is local development-fixture evidence; it is not physical-rule, release, or deployed-service approval. Existing [landing-to-game UX plan](landing-to-game-ux-plan.md) and [UI redesign plan](ui-ux-redesign-plan.md) contain recommendations, but their journey descriptions must be reconciled with current runtime behavior before they serve as a current-state audit.

## Findings and priorities

1. **P1 — Account and recovery coverage is fixture-backed and incomplete.** A browser verifier now covers registration, sign-in, recovery-request feedback, profile/stat/leaderboard display, username changes, sign-out, delete cancel/accept, seat link/resume, delayed account switching during login/link, and email verification followed by guest-session restoration. Durable API behavior and service failure/loading states still need coverage.
2. **P1 — Leaf inventory exists, but the interaction audit is incomplete.** Independent source reviews found omitted controls: the primary action dock, movement checklist, board-event reward choices, Settings controls, recorded duel results, attack-history navigation, the in-game account-panel instance, a separate first-match guide, unsupported-browser fallback, multi-unit retreat choice box, and deployment Cancel placement action. The move context also has route cancellation and a distinct End all movement command, and monster retreat uses board-cell selection. These leaves are now named in the inventory. The setup troop-placement sheet and move piece-details disclosure each have one desktop browser path; tablet/phone, undo/cancel, role, error-state, and accessibility coverage remain open. Most other leaves still have only source/render evidence; browser interaction, role, focus, close/cancel, viewport, and error-state coverage must be recorded per leaf before this audit is closed. Continue reconciling the ledger against source during implementation.
3. **P1 — Choice boxes, native confirms, and drawer modality need separate coverage.** A second independent pass identified Blonde Lure, Toxicor Mutation, Stabilizer Ray, the multi-unit retreat choice box, browser-native leave/disappear/concede/delete confirmations, and different focus semantics between the nonmodal Military drawer and modal Monster Sheet. These are explicit leaf rows. Concede cancel/accept and account deletion cancel/accept have fixture evidence; safe leave/disappear prompts, preference-disabled behavior, a retreat flow generated by a real Fight resolution, and full modality/accessibility checks remain open. Account deletion uses its own confirmation and is independent of the leave/concede/disappear preference.
4. **P1 — The Home entry funnel now has fixture-backed browser acceptance, while adjacent outcomes remain partial.** `browser:home:verify` proves keyboard access to the main disclosures, 2/3/4-seat propagation, a completed solo setup into a legal Move action, and desktop/tablet/phone/320px overflow bounds. The lobby error/recovery paths, each playtest tool's full return path, touch-only operation, and loading/error presentation remain open. `landing-to-game-ux-plan.md` continues to distinguish current entry points from proposed IA recommendations.
5. **P2 — Responsive evidence is gameplay-heavy.** The corrected local interaction matrix exercises 1280×720, 900×700, 768×600, 834×1112, and 390×844 setup/game flows, while 320×740 has a focused tray/layout check. Account/profile has fixture-backed 390×844 and 320×740 bounds, but complete Home, lobby, recovery, and real account journeys lack equivalent viewport evidence; touch input and browser-engine coverage remain incomplete.
6. **P2 — Error and edge states are under-covered.** Prioritize API failures/loading/empty states, room validation and capacity, invite clipboard fallback, reconnection/stale sessions, cancel paths, and terminal navigation.
7. **P2 — Visual and component checks do not prove interaction behavior.** Keep render verifiers, automated browser assertions, and human visual/assistive-technology review as separate evidence types.

## Ledger update rule

For future work, split a grouped row when a submenu or role has a distinct entry point or choice state. Each evidence update should record the browser/device and viewport, input method, script or artifact, assertions/results, date, and any remaining manual check. Change a row to **Covered** only when its defined states and input methods have evidence; a partial happy path is not enough.
