# Security and abuse-control baseline

The API now applies a bounded in-memory request limiter to every HTTP request and a separate connection-attempt limiter to WebSockets. The defaults are 120 HTTP requests per source address per 60 seconds and 30 WebSocket handshakes per source address per 60 seconds. A rejected HTTP request returns `429` with `Retry-After: 60`; a rejected WebSocket closes with code `1013`. These are process-local controls, so production deployments still need an edge or shared limiter for multi-instance abuse resistance.

`GET /health` now probes the selected persistence boundary: memory reports its local boundary, while Prisma executes `SELECT 1`. A failed persistence probe returns `503` and emits a redacted persistence error report instead of claiming the service is healthy.

JSON responses set `no-store`, `nosniff`, `DENY` framing, and `no-referrer` headers. CORS uses `ALLOWED_ORIGIN` when configured and otherwise retains the development wildcard. Room tokens are not logged or included in error payloads. Rate-limit behavior is covered by deterministic unit tests in `apps/api/src/rate-limit.test.ts`.

The Vercel static client now applies an enforcing Content-Security-Policy and transport, MIME, framing, referrer, and browser-permission headers to every response using `apps/web/vercel.json`. `npm run security:headers:verify` locks the policy, including a script policy without inline/evaluated scripts; after `npm run build`, `npm run security:headers:browser:verify` serves the production bundle with those headers and checks that Chrome renders without policy violations. Its `connect-src` currently permits same-origin APIs and WebSocket transports; add the exact approved API origin there if hosting uses a separate origin. A live read-only check on 2026-10-10 found HSTS at the current Vercel site but no CSP, frame, MIME, referrer, or permissions policy headers. The configuration is not effective on the deployed site until a reviewed deployment is made and its responses are rechecked.

The local PostgreSQL persistence runner now provisions a distinct application runtime role with table/sequence CRUD and no schema-DDL, superuser, database-creation, role-creation, or replication privileges; it checks those grants and runs the persistence suite under that role. This proves the local application path can operate with a restricted role, but does not prove the hosted role is configured correctly. Remaining release work includes deployed verification of static and API headers, a reverse-proxy policy, shared/distributed limits, independent threat-model review, live database permission review, backups, restore, and credential rotation. Those checks require a configured deployment and are intentionally not claimed by the local baseline.

Production dependency risk is checked by `npm run security:dependencies:verify`. It runs `npm audit --omit=dev` and compares the result with `config/production-audit-baseline.json`. On 2026-10-07, npm overrides pinned Prisma's vulnerable transitive `deepmerge-ts` and `mysql2` packages to patched releases while preserving Prisma 7. A fresh run on 2026-10-11 passed against the current lockfile with zero production vulnerabilities and no known blockers. Database permissions, backups, restore, credential rotation, deployment proxy policy, and distributed rate limits still require a configured deployment and review.

The API also exposes a token-free `/metrics` JSON snapshot with request failures, accepted/failed commands, latency sample totals, reconnects, WebSocket successes/failures, completed/abandoned rooms, and server errors. It additionally counts every redacted error report, WebSocket projection divergence report, and API deployment failure (`errorReports`, `divergenceReports`, and `deploymentFailures`) so a deployed scraper can alert on those categories without receiving private state. A bounded local error reporter redacts token-bearing paths, categorizes HTTP/command/WebSocket failures, and emits a threshold alert log event; it is still not a substitute for durable external metrics or alerting.
