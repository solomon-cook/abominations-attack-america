Vercel is selected and used for static delivery, with a Vercel Functions HTTP API and Prisma Postgres now configured as the multiplayer candidate. The existing Production project has a public URL, but its currently served deployment still lacks the API routes and points to an old client bundle. A separate Preview project and Prisma Postgres database have been used for synthetic staging. The Preview has passed two-browser create/join, setup, legal action, shared authoritative state, and reload recovery. Production health and configuration remain unverified; see the current dated probe below.

## Options and decision criteria

The eventual provider must support the requirements in [`docs/deployment-requirements.md`](deployment-requirements.md): static web delivery, durable API compute, WebSockets and polling fallback, managed Postgres with Prisma migrations and backup/restore, environment-scoped secrets, and observable health and failure signals. The decision must be based on those capabilities and on a reversible operational path, not on provider branding.

The following must be recorded before selection:

- separate staging and production URLs, databases, credentials, allowed origins, logs, and alert destinations;
- HTTPS/WSS and proxy upgrade behaviour, request/time-out limits, rate-limit controls, and secret rotation;
- migration ownership, backup retention, restore access, rollback strategy, and incident escalation;
- cost, access ownership, regional/data handling constraints, and an exit path.

## Free and Prisma-compatible hosting decision

**Constraint:** use a fully free setup, or use Prisma Postgres as the database. The previous Render Hobby API-plus-Render-Postgres recommendation and its $13/$19/$26 monthly estimates are withdrawn; do not provision the Blueprint as written. Paid API compute remains an option when paired with Prisma Postgres. A Vercel Preview project and a separate Prisma Postgres database have been provisioned for synthetic staging only; the current account tools do not expose the database plan, and no production resources, aliases, or environment values were changed.

**No-always-on API candidate:** keep the static Vercel frontend and expose the API as Vercel Functions with Prisma Postgres as the only database. The deployed implementation uses short HTTP handlers and the existing polling fallback; WebSockets remain disabled. This avoids operating an always-on API process, but still requires durable storage and server-side credentials. Vercel Hobby includes up to 1 million function invocations monthly and is limited to personal/non-commercial use; the owner confirmed this is a non-commercial hobby app. Prisma Postgres Free includes 200,000 operations monthly and no automated backups, so this combination remains a test preview only. The latest Preview build has passed two-profile room setup, a server-accepted legal action, shared-state observation, and reload recovery. Actual operation usage and a tested backup/restore path remain open. See [Vercel Hobby plan limits](https://vercel.com/docs/plans/hobby) and [Prisma Postgres pricing](https://www.prisma.io/pricing).

The nearest no-cost option is the existing static frontend plus one Render Free Node API service, with separate Prisma Postgres Free databases for staging and production. This is a disposable preview/playtest path only: Render explicitly says not to use Free instances for production; its API service sleeps after 15 minutes without inbound HTTP/WebSocket messages, can take about a minute to wake, may restart, and has no persistent filesystem. Render Free also cannot run its pre-deploy migration command, so a later pipeline must apply migrations from GitHub Actions using the direct database URL before deploying. See [Render Free limits](https://render.com/docs/free) and [Render deploy commands](https://render.com/docs/deploys).

Prisma Postgres Free is $0 and includes 200,000 database operations per month, 2 GB storage, 50 databases, and workspace-shared quotas; the current docs say it has no automated backups. The 500 MB shown in the pricing page's example usage is not the Free plan limit; the plan table and Free tutorial both list 2 GB. Each database query counts as an operation. The existing documented presence scenario of 100 continuously visible opted-in tabs produces about 8.64 million heartbeat writes per month, far over the free quota. Keep that scenario out of any free-host capacity claim; measure real query volume or disable/retune presence before considering free-plan public use. Prisma Postgres Starter is currently listed at $10/month and includes 1 million operations, 10 GB, and daily backups retained for 7 days. At $8 per million operations above the included amount, the 100-tab heartbeat scenario alone would cost about $61 in operation overages, before ordinary gameplay queries. This makes the Starter database practical only if measured traffic stays low or presence writes are substantially reduced. See [Prisma pricing](https://www.prisma.io/pricing), [Prisma free-plan quickstart and limits](https://www.prisma.io/docs/full-stack-tutorial), and [Prisma backups](https://www.prisma.io/docs/postgres/database/backups).

This app's PostgreSQL notification path is locally verified across two API processes but is not used by the Vercel HTTP adapter. Vercel Functions have finite invocation lifetimes, so any future WebSocket use would require reconnect and durable-state restoration; each socket is pinned to one function instance and cross-instance fanout must use shared infrastructure. Keep all Prisma credentials server-side. ## Release evidence gate

Until those slots contain source-linked, reviewable evidence, deployment status remains open. Local tests, builds, and documentation do not fill hosted environment, managed-database, backup/restore, or approval evidence.
