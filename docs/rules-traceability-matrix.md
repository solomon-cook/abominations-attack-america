# Rules traceability matrix

This matrix maps each section of [the rules reference](monsters-menace-america-rules.md) to current prototype code, interface, and fixture/test coverage. The `Status` column describes **development implementation coverage only**: `Foundation` means implemented but simplified, `Partial` means some behaviors are present, and `Unresolved` means implementation or evidence is still missing. None of these statuses means that a rule has been verified against the user's physical edition or approved for release. Source verification is tracked separately in [the unresolved inventory](unresolved-rules-inventory.md); release approval is tracked in [the release proof report](release-proof-report.md) and the relevant promotion/sign-off record.

## Source authority order

When sources disagree, record the conflict rather than silently choosing a value. The user's physical edition (rulebook, board, records, and cards) is authoritative. Until it has been inspected, project photographs and catalogue transcriptions remain candidate evidence; hosted scans and player aids may corroborate a question but cannot close a conflict. After the physical source is recorded, the review order is:

1. The user's printed board, rulebook, component records, and card faces for physical placement, labels, statistics, inventories, and card text.
2. The consolidated rules reference for the rules interpretation and timing summary.
3. `docs/rules-source.md` for an explicitly documented digital adaptation.
4. Engine behaviour, then UI wording, only after the preceding source has been recorded.

The component catalogue is a transcription/reference candidate based on project evidence, not proof of physical-edition review or a licence to ship third-party artwork. Any unresolved rule-bearing fact remains unresolved in this matrix and in the rules reference's final inventory.

## Gaps that block the next release gate

Prototype coverage is not proof of physical-rule fidelity. The regular local and room-game initializer pins the photo-transcribed `AUDITED_BOARD` candidate (`human-audited-north-america@1`); `FULL_HONEYCOMB_BOARD` and `PROVISIONAL_AUTHORITATIVE_BOARD` are distinct records. See the [board provenance reconciliation](board-source-status-reconciliation.md) and [promotion sign-off](board-promotion-signoff.md). The physical board remains pending comparison; explicit checks cover feature co-locations, Great Lakes classifications/barriers, lair identity, setup order and unused-branch placement, and the Navy Nuclear Submarine choice/launch lifecycle. Keep the user's edition as the deciding source, and leave disputed board, component, and card facts unresolved until checked against it. Deterministic commands, setup transitions, path movement, combat, encounters, Research effects, and Challenge behavior have development coverage at differing levels, but that coverage does not close source verification or release approval.
